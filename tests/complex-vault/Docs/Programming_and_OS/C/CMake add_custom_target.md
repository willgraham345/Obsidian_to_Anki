# Summary
󰙎 add_custom_target ;;; CMake command that defines a custom build target (usually to run scripts or generate files) without creating a library or executable. Usually titled a 'utility' within CMake targets. Use `add_custom_command()` to generate a file with dependencies. Useful for command line arguments with specific arguments/options (i.e. doxygen, cppcheck) or really specific workflows.

# Additional Background
## Media
[add\_custom\_target — CMake 4.0.1 Documentation](https://cmake.org/cmake/help/latest/command/add_custom_target.html)

## Usage  
- Use `ALL` to make the target run automatically with the default build.  
- Add the target as a dependency of other targets with `add_dependencies`.  
- Ideal for code‑generation, documentation builds, or any custom command that should be part of the build pipeline.

## Syntax  
 `add_custom_target(<name> [ALL] [COMMAND <cmd1> [ARGS] [<...>]] [BYPRODUCTS <files>...] [WORKING_DIRECTORY <dir>] [DEPENDS <depend1>...] [USES_TERMINAL])` ;;; core signature  

 `add_custom_target(GenDocs ALL COMMAND ${CMAKE_COMMAND} -E echo "Generating docs")` ;;; always‑run target that prints a message  

 `add_custom_target(CompileProto DEPENDS ${CMAKE_CURRENT_SOURCE_DIR}/proto/*.proto COMMAND protoc …)` ;;; target that depends on .proto files and runs protoc

## Examples  
- **Generate a header from a script**  
   `add_custom_target(GenHeader COMMAND python gen_header.py WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR})` ;;; runs a Python script to create a header file  

- **Run unit tests after each build**  
   `add_custom_target(RunTests ALL COMMAND ${CMAKE_CTEST_COMMAND} --output-on-failure)` ;;; executes CTest every time the default build runs  

- **Package documentation**  
   `add_custom_target(DocBundle BYPRODUCTS ${CMAKE_CURRENT_BINARY_DIR}/docs.zip COMMAND zip -r ${CMAKE_CURRENT_BINARY_DIR}/docs.zip ${CMAKE_CURRENT_SOURCE_DIR}/docs)` ;;; creates a zip bundle of the docs folder

## Flashcards  
󰠗 What does the **ALL** keyword do in `add_custom_target`? ;; It makes the target part of the default build, so it runs whenever you invoke `make` (or the generator’s equivalent) without specifying a target.  

󰠗 How can you ensure a custom target runs only when its dependencies change? ;; Omit **ALL** and add the target as a dependency of another target with `add_dependencies`; CMake then decides based on timestamps.  

󰠗 Which option tells CMake which files the target will produce? ;; `BYPRODUCTS` lists the files generated by the target, enabling proper up‑to‑date checks.
