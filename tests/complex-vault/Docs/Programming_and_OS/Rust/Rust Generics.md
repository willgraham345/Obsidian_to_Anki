󰙎  Generic types ;;; Types that take one or more types as parameters, a template for making types. Concerned with what something *is*. Called as: `struct Foo<T, U> { ... }`  =
󰙎  Generic functions ;;; Functions that takes types as parameters, in addition to values (i.e. `fn foo<T>(x: T, y: T) -> T`). Called as `foo::<i32>(1, 2)` or `foo(1,2)`  =
󰙎  Monomorphization ;;; Rust-ism which describes the process of turning generic code into specific code. It performs this by filling in the concrete types that are used when compiled. In this process, the compiler looks at all the places where the generic code is called and generates code for the concrete types. =

## Usage
  `struct S<T> ...` ;;; Generic struct `S` with a generic type parameter `T`, where `T` is a placeholder. T needs to be included at some point in the struct definition.

  `struct S<T: R>` ;;; Shorthand version of `S<T> where T: R`. Stipulates that `T` has trait `R` implemented for generic struct `S`. 


  `fn f<T>(s: SGen<T>)` ;;; Generic function over `T` 

  `"42".parse::<i32>()` ;;; Use the __generic__ function `parse` to parse var `a`, which is a string, into the `i32` type.


See also [[Rust trait]]

## Syntax %% fold %% 
Type `T` becomes generic when there is a `<T>` before it
- NOTE: `<T: ...>` introduces a trait bound, *not* a generic.
